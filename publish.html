Publish your data

The last step in working with you Metabarcoding data (apart from analysing your dataset and draw biologigal meaning from it) is the publication of the data. Raw reads and ASV tables published under FAIR principles.

As mentioned before we advise to publish raw reads and ASV tables simultaneously via the GFBio Submission Service.

Raw reads

For the submission of raw read see the information here

ASV tables

For the publication of ASV tables to the ASV Registry and further on to GBIF use the GFBio Submission Service. Here, choose the template for Metabarcoding data (under Other templates), or download it below

The template

The Metabarcoding submission template has four sheets: read_me, dataset_info, collection_sites, asv_sequence_data, example_asv_data, description

Please refer to the read_me and description sheets for information on how to fill out the template and the example_asv_data for an example of how to fill out the asv_sequence_data sheet.

Below you will find the explanation sof the three sheets (dataset_info, collection_sites and asv_sequence_data), that have to be filled out for every submission:

dataset_info

Dataset Title A short, concise title mandatory
Dataset Details Free-form text containing a longer description of the project mandatory
Dataset URL URL pointing to an online source related to the current project, which may or may not serve an updated version of the description data if available
Contact Person Name Name of the content/administrative contact person - Questions and feedback about data, or restrictions on use of the data should be directed to the adminstrative contact. This contact normally represents the agent acting as the original supplier or custodian of the dataset. mandatory
Contact Person Email Email of contact person highly recommended
Owner Organisation Full organization or corporate name in multiple languages (en: 'Botanical Garden of ...', de: 'Botanischer Garten von ...'). The Label mechanism also supports acronyms / abbreviations. - Entity having legal possession of the data collection content. Here defined for the entire data collection, not for individual units (an owner statement on the unit-level would override this dataset-level statement) highly recommended
Owner Person/Full Name Name of an individual person highly recommended
Owner Role Functional contact name, e.g. "Database administrator", "The Director", etc. optional
License To be used if data are placed under a public license (GPL, GFDL, OpenDocument). Placing data under a public license while maintaining copyright is recommended! mandatory
Terms Of Use Defines conditions under which the data may be analised, distributed or changed. "Terms of use" includes concepts like "Usage conditions" and "Specific Restrictions". highly recommended
Additional Author 1..n Name Name of author if available
Additional Author 1..n Email Email of author if available
Reference Literature Title Title of the referenced literature if available
Reference Literature Details Details on the referenced literature if available
Reference Literature DOI DOI of the referenced literature mandatory, if literature is given

collection_sites

Source institution Unique identifier (code or name) of the institution holding the original data source (first part of record identifier). In specimen collections, this is normally the institution or private holder of the collection itself. For herbaria and botanical gardens, the standard abbreviations should be used. mandatory (in doubt = owner organisation)
Source of record Name or code of the data source (unique within the institution, second part of the record identifier) mandatory
DateLastEdited Date of last change (or creation for first version) of this unit record. recommended
Recordbasis An indication of what the unit record describes, using controlled vocabulary (see description sheet for details) mandatory
Sample-ID short name or identifier of the sampling site (e.g. identifier of Malaise-Bottle, collecting site) unique within source, used in table asv-sequence_data to connect data mandatory
Date and time (ISO) Date (and time) of the collecting or observation event, expressed in a date type (convertible to an ISO 8601 standard structured format). If you want to state a period, use this field for its beginning and an additional one for its end. If it is impossible to use a date format, use a DateText field instead. highly recommended
Gathering agent The person, or one of the persons or team(s) or organization(s) responsible for collecting or recording. recommended
LocalityText Original locality data as appearing on a label or in an original entry. recommended
Country Name of country or major region for specimen or observation (for marine areas see element "Named area") if continental locality
Named area Name of a geographic, geomorphological, geoecological, or administrative area (used alternatively to country; applicable in marine areas) if marine locality
Site longitude (decimal) Longitude expressed in decimal degrees highly recommended
Site latitude (decimal) Latitude expressed in decimal degrees highly recommended
Site coordinate type (spatial datum) Mathematical surface on which the mapping and coordinate system used for the geocodes of the record are based (for GPS "WGS84" in general) only applicable if coordinates are present, then mandatory
collecting method method used for collecting specimens (e.g Malaise-trap, hand fang) recommended
File URL/URI Universal Resource Identifier (URI) of the underlying multimedia file, i.e. "naked" path to electronic source of multimedia object (e.g. web address). If your material is sent to and published by GFBio, the URI will be set. for each multimedia object
Creator Identifier, e.g. name or other id, of (technical) personnel who has taken the image. Does not imply copyrights or other rights. highly recommended
License To be used if data are placed under a public license (GPL, GFDL, OpenDocument). Placing data under a public license while maintaining copyright is recommended. highly recommended
MeasurerandFact1 A container for quantitative and categorical measurements (including observations) refering to the unit, e.g. counts, size measurements, colours, etc. optional
MeasuredValue1 Value for measured fact optional
MeasurementUnit1 Unit of measured fact optional

asv_sequence_data

pcr-primer_fwd Used forward primer for pcr mandatory
pcr-primer_rev Used reverse primer for pcr mandatory
primer target Target of the used primer mandatory
seq-primer Used primer for sequencing recommended
sequence Sequence of operational taxonomic unit (OTU) or amplicon sequence variant (ASV) found in the sample mandatory
record identifier Unique identifier within this source mandatory
Reference database 1 Name of reference database (e.g. BOLD, NCBI) mandatory
URL_database 1 URL to reference database (e.g. https://boldsystems.org) mandatory
result 1 Result of blast 1 (taxonnames ordered by ranks, see example column H-M in the template), add as many columns as needed mandatory
Taxon reference in database 1 URI to taxon in reference database (see example column N in the template) recommended
%-identity 1 Grade of identity of sequence with reference database in % (see example column O or AR in the template) recommended
Reference 2 Possibility for another results block from a different reference, divided as above optional
Sample-ID 1 name of the first collection site (as referenced in sheet collection_sites J4) in column header and all reads per ASV/OTU for the taxa and sampling site in cells below (see example column Z in the template) mandatory
Sample-ID [..] name of the x. collection site (as referenced in sheet collection_sites Jx) in column header and all reads per ASV/OTU for the taxa and sampling site in cells below. As many as you have samples.
