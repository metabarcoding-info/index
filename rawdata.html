Raw data

The easiest way to publish your raw data on one of the INDSC databases (such as the European Nucleotide Archive) is via the GFBio Submission service.

There you can sign up for an account and create a new submission. For your raw read files you can choose the molecular data template (either on the page or here), fill it out and upload it alongside your data files. For a description of the metadata fields and their usage, please see the link during the submission or here

In case you want to upload your data to ENA yourself, please check possibilities and make yourself familiar with the official ENA guide. Afterwards, you can submit your files i.e. through the ENA Webin Portal, by taking the following steps, after creating an account:

  • Register a study (Where you are asked to set a study name and a release date, as well as provide a descriptive study title and abstract)
  • Register your samples (Where you can choose an appropiate template to download, fill out and upload (see below for exapmle and details))
  • Upload you sequence files by one of the methods suggested in the official guide (important: upload your sequence files first before registering raw reads!)
  • Register your raw reads (Where you again can choose the appropiate template, fill it out and upload it, thereby binding the study, samples and raw reads together (see below for example and details))

Registering samples:

In order to register samples, you can download one of the sample checklists from the ENA Webin portal, depending on your study design and scope. Each table contains mandatory fields, which have to be present, as well as optional fields (chosen from the list when preparing to download). There is also the possibility to add custom fields, to contain information, that is not covered by one of the standard fields from ENA. After successful registration of the samples, it is possible to download the resulting sample accession numbers (needed for the registration of raw reads)

As a minimal example, a spreadsheet would contain the columns:

tax_id an NCBI taxonomy ID (for Metabarcoding sample, where there will be different species present in the sequences, NCBI Taxonomy provides a list of metagenome identifiers, which an be used here. Refer to NCBI Taxonomy to find the appropiate ID for your study)
scientific_name The name associated with the chosen tax_id
sample_alias A unique identifier for each of the samples.
sample_title A short title for the samples. (Does not need to be unique. Can be used to group re-runs, triplicates, etc.)
sample_description A short description of the samples.
collection date Date of collection (Must be ISO8601 compliant, such as "2026-08-26".)
geographic location (country and/or sea) One entry from the INSDC list of countries.
lat_lon Geographical coordinates of the location where the specimen was collected
geographic location (region and locality) A more precise description of the location. (Such as federal state, province, city, etc.)
environmental sample Yes/No (to distinguish actual samples from controls)

Example:

Checklist ERC000011:1.3 ENA default sample checklist
tax_id scientific_name sample_alias sample_title sample_description collection date geographic location (country and/or sea) lat_lon geographic location (region and locality) environmental_sample
#units
1628154 pollen metagenome Sample_1.1 Sample_1 associated plant traces from sweep netting 2026-08-26 Germany 51.411, 9.429 Hesse, Kassel Yes
1628154 pollen metagenome PCR_blank_1 PCR_blank PCR blank control missing missing No

The first row contains information about the checklist, that was downloaded, the second row contains the column names for the netadata fields. The third row is only needed for custom fields, where you need to denote the unit in which values in your custom fields are measured.

Registering Raw Reads:

In order to register your raw reads, the files must first be uploaded to the ENA servers (by one of the methods from the official guidelines). Then, one of the spreadsheets for read submission can be downloaded from the ENA Webin Portal, filled, and uploaded. Equivalent to the sample submission, there are different temlates, depending on your study design (single reads, paired reads, etc.) and data type (Fastq, BAM, etc.)

A minimal example for paired reads in fastq files:

sample The identifier of the sample corresponding to the read files in this row (after registering the samples)
study The identifier for the study, which was registered in the first step
instrument_model One of the list available models of sequencers (see permitted values for this field in the ENA documentation)
library_name A unique name for the library (Can be the same as for the samples, if there is a 1:1 correlation)
library_source The type of source material that was sequenced (see permitted values for this field in the ENA documentation)
library_selection The method to select, or enrich the material being sequenced. (see permitted values for this field in the ENA documentation)
library_strategy The sequencing technique intended for this library. (see permitted values for this field in the ENA documentation)
library_layout SINGLE/PAIRED, depending on type of sequencing
forward_file_name Name of the file containing the forward reads, that was uploaded to the ENA server
forward_file_md5 Forward file checksum (usually delivered from the sequencing facility along with the actual read files)
reverse_file_name Name of the file containing the reverse reads, that was uploaded to the ENA server
reverse_file_md5 Reverse file checksum (usually delivered from the sequencing facility along with the actual read files)
FWD_NAME1 Name of the forward primer used during amplification
FWD_SEQ1 Sequence of forward primer used during amplification
REV_NAME1 Name of the reverse primer used during amplification
REV_SEQ1 Sequence for the reverse primer used during amplification

In this example, the names and sequences of the primers used during amplification of the libraries were added as custom fields, since it is important information for reproducability and reusability to have the primer sequences directly attached to the read files.
